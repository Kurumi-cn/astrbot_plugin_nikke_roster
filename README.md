# NIKKE 练度统计助手（AstrBot 插件）

在 QQ 里收集 NIKKE 练度数据并出图：把网页端导出的**分享码 / JSON** 导入，按 QQ 分存档保存，
再出**角色面板图**、**练度统计表**和**群内词条排行**。出图是 Pillow 手绘——不跑浏览器、不截图。

- 数据来源：网页端 <https://kurumi-cn.github.io/nikke-photos/>（在那里录数据、导出分享码）
- 运行环境：AstrBot + OneBot 协议端（NapCat 等）
- 插件目录名：`astrbot_plugin_nikke_roster`

## 功能一览

| 类别 | 能做什么 |
| --- | --- |
| 导入 | 分享码（角色数据 / 表格配置）、整档 JSON 文件 |
| 存档 | 每人最多 8 个存档；新建 / 删除（自动备份）/ 改名 / 切换 / 查看；旧单档数据自动迁移 |
| 出图 | 角色面板图（随机皮肤、立绘自动对齐）、练度统计表、群内词条排行 |
| 改数值 | 同步器、好感、星级、核心、技能、爆裂；以及"一键改全部已导入角色" |

## 安装

1. 需要 AstrBot（官方镜像已自带 Pillow）
2. 把插件目录放进 AstrBot 的 `data/plugins/`（目录名保持 `astrbot_plugin_nikke_roster`）
3. **无第三方依赖**：`requirements.txt` 刻意留空——出图用 Pillow（镜像自带），其余全是标准库。
   好处是安装时不会因 pip 源 / 网络 / 版本冲突失败
4. 素材（立绘 / 头像 / 技能图标，约 100MB）不在仓库里，见「素材」一节
5. 重载插件，在 AstrBot 后台配置下面三项

## 配置项（`_conf_schema.json`）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `web_base_url` | 空 | 网页端地址；用于 `/妮姬帮助` 与 `/妮姬网址`。留空则 `/妮姬网址` 提示未配置 |
| `help_use_forward` | 开 | 群聊里把帮助发成合并转发（不刷屏）；私聊始终纯文本；协议端不支持时自动退回纯文本 |
| `random_skin` | 开 | `/妮姬面板` 每次从该角色立绘里随机挑一张（含默认立绘）；只有一张立绘的角色不受影响 |

## 命令

**基础**
- `/妮姬帮助` — 显示本帮助
- `/妮姬网址` — 输出网页端地址
- `/妮姬自检` — 检查角色表、素材、字体、数据目录是否就绪

**数据**
- `/妮姬导入 <分享码>` — 导入分享码（角色数据、表格配置）
- `/妮姬导入json` — 2 分钟内单独发送 JSON 文件，整档存入练度库
- `/妮姬列表` — 查看已经导入了的妮姬（人数多时发合并转发）

**存档**
- `/妮姬存档` — 查看当前存档与全部存档
- `/妮姬新建存档 <名字>` / `/妮姬删除存档 <名字>`（删除前自动备份）
- `/妮姬修改存档 <原名> <新名>` / `/妮姬切换存档 <名字>`

**出图**
- `/妮姬面板 <角色>` — 该角色的练度面板图
- `/妮姬练度统计` — 一张练度统计表（人数多时拆图进合并转发）
- `/妮姬群排行 <角色>` — 仅群聊；按群成员名单出词条排行表，每图 30 人，每 QQ 15 秒 CD
- `/妮姬练度统计设置 <角色> <角色> ...` — 定表格里有谁、按什么顺序排（推荐从网页端导入表格配置码后再用）

**改数值**（均为"改自己当前存档"）
- `/妮姬同步器 <1~2000>`、`/妮姬好感 <0~40>`、`/妮姬星级 <0~3>`、`/妮姬核心 <0~7>`
- `/妮姬技能1 <1~10>`、`/妮姬技能2 <1~10>`、`/妮姬爆裂 <1~10>`
- 一键版：`/妮姬一键好感度`、`/妮姬一键星级`、`/妮姬一键核心`、`/妮姬一键技能1`、`/妮姬一键技能2`、`/妮姬一键爆裂`

> 群里使用要带 `/` 前缀；私聊可以不带。取值范围的"真源"在网页端，改动需两边同步。

## 数据从哪来

1. 网页端「BOT 分享」页生成**分享码** → `/妮姬导入 <分享码>`
2. 网页端「存档管理 → 导出当前档案数据」的 **JSON** → `/妮姬导入json`（按提示单独发文件）
3. 表格配置：网页端「词条统计」页导出**表格码** → `/妮姬导入` → 之后 `/妮姬练度统计` 就按这份名单出表

## 素材

- 服务器部署时：本地用 `tools/upload-assets.ps1` **一次性上传**；`deploy.ps1` 只传插件目录里的文件，
  不会碰服务器上已有的素材（所以日常更新代码不会重传 100MB）
- 缺失素材不会崩：缺哪张就跳过哪张（`missing_assets()`），`/妮姬自检` 会报出来
- 发布策略（待办）：发布包内含素材 **+** 另提供单独下载方式；Git 仓库不直接托管那 100MB
  （避免仓库臃肿、也避开单文件体积上限）

## 已知限制

1. 群里昵称里的 emoji 与生僻字画不出来（字体子集只有 GB2312 常用字 + 卡片用字）
2. 立绘自动对齐只做水平方向，垂直方向（上下留白不一致）未处理
3. 分享码里没有立绘字段 → "随机皮肤"是绕过它的做法；网页端选的皮肤传不过来
4. 合并转发里放图片节点，真 QQ 客户端未实测（AstrBot 侧已用假协议端验证，代码里有降级为逐张直发的兜底）
5. 角色表是网页端的整份拷贝：网页端加了角色后，要重新拷贝 roster.json 并补传该角色的素材

## 开发 / 部署

目录结构：

```
bot/
├── astrbot_plugin_nikke_roster/   # 插件本体（部署到容器）
│   ├── main.py                    # 唯一入口：注册指令 → 取参数 → 调 core → 发结果
│   ├── core/                      # 业务逻辑（与框架解耦，可单独测）
│   ├── assets/                    # 角色表与字体（图片素材在服务器上）
│   ├── _conf_schema.json          # 配置项
│   └── metadata.yaml
├── tools/                         # 部署与调试脚本
└── seed/                          # 预览输入、别名种子、分享码测试向量
```

常用命令（PowerShell）：

```powershell
# 出图预览（真实素材 + 真实字体，不连服务器）
python tools/render-preview.py seed/preview

# 立绘对齐前后对比
python tools/art-align-compare.py --top 20 --controls 4 --scale 1

# 部署：同步 + 编译检查 + 重启 + 两套冒烟（要求硬失败 0 / 软失败 0）
powershell -File tools/deploy.ps1
```

- 冒烟脚本 `tools/smoke.py` / `tools/command-smoke.py` 依赖容器里的 `astrbot` 模块，**只能部署后在服务器上跑**
- `deploy.ps1` / `upload-assets.ps1` 必须 **ASCII-only**（PowerShell 5.1 按 GBK 读无 BOM 的 ps1，中文会解析失败）
- 交接文档与文案清单在工作区 `文档/`（`BOT插件-交接文档.md`、`BOT文案清单.md`）
